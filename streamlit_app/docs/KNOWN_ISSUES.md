# Known issues in Masgent (v1.1.19, local clone)

None of these were patched in `src/masgent/`. Each entry says how the Streamlit
frontend works around it and suggests a fix for upstream. Line numbers refer to
the local files at the time of writing.

| ID | Severity | File:line | Problem | Frontend workaround | Suggested fix |
|---|---|---|---|---|---|
| K01 | High (blocks 6 tools without POTCARs) | `utils/tools.py:291, 1168, 1198, 1295, 1367, 1457, 1551` | Every VASP-input/workflow generator calls `vis.potcar.write_file(...)`. Without `PMG_VASP_PSP_DIR` (licensed POTCAR library) pymatgen raises and the whole tool fails, even though INCAR/KPOINTS/POSCAR could be produced. | Worker installs a runtime hook (in the worker process only, `core/hooks.py`): if no PSP dir is configured, `VaspInputSet.potcar` returns a placeholder whose `write_file(p)` writes `p.spec` listing the required POTCAR symbols and the shell command to assemble them on the cluster. If a PSP dir is configured in Settings, real POTCARs are written (never displayed, never zipped). | Catch the missing-PSP error and write a `POTCAR.spec` (or skip POTCAR) with a warning. |
| K02 | High | `utils/tools.py:1136, 1144` vs `utils/schemas.py:886` | Tool default/annotation is `test_type='both'` but the schema accepts only `'kpoints'\|'encut'\|'all'`, so calling the tool with defaults always fails validation. | UI offers `kpoints / encut / both` and sends `'all'` for "both" (the tool's `else` branch runs both tests). | Align the schema and the tool on one literal (`'both'`). |
| K03 | High (CLI) | `cli_mode/cli_entries.py:436-439` | Menu 3.5 shows `3.5.1`/`3.5.2` but matches `startswith('3.4.1')`/`'3.4.2'`, so the pretrained predictors are unreachable from the CLI. `utils.print_help` also labels them 3.4.x. | UI calls the tool functions directly (ML toolkit → Pretrained models). | Match on `'3.5.1'`/`'3.5.2'`. |
| K04 | Medium | `utils/tools.py:2967 vs 2986`, `3089 vs 3125` | Pretrained predictors write `AlMgSiSc_prediction.txt` / `AlCoCrFeNi_prediction.txt` but return `ml_…_prediction.txt` (file does not exist). They also return no numeric values. | Runner collects files by scanning the run folder; `core/parsers.py` parses the txt into numbers for display. | Return the real path and the predicted values in the dict. |
| K05 | Low | `utils/schemas.py:1001` vs `utils/tools.py:1422` | AIMD `md_timestep` default is 2.0 fs in the schema but 5.0 fs in the metadata; the function signature has no defaults at all, and metadata lists `temperature` while the parameter is `temperatures`. | UI always passes all four AIMD parameters (defaults from metadata: 5.0 fs). | Give the function signature defaults and harmonise names. |
| K06 | High (Windows) | `cli.py:3`, `cli_mode/cli_entries.py:3`, `cli_mode/cli_run.py:4`, `ai_mode/ai_backend.py:8` | `bullet` imports `termios`, which does not exist on Windows. `masgent` CLI and `masgent.ai_mode.ai_backend` cannot be imported on Windows at all. | Frontend never imports `cli_mode`/`ai_mode.ai_backend`; `core/agent.py` rebuilds the same pydantic-ai Agent (same system prompt via `utils.load_system_prompts`, same tools, same 20-message history window, same provider/model names). | Import `bullet` lazily or use a cross-platform menu library (e.g. `questionary`). |
| K07 | Medium | `ai_mode/ai_backend.py:350-385` | `tools.analyze_vasp_workflow_of_neb` is not registered on the agent (35 of 36 tools). | Frontend agent registers all 36 tools (configurable in `core/agent.py`; documented in the assistant page). | Add it to the `tools=[...]` list. |
| K08 | Medium (Windows) | `ai_mode/ai_backend.py:62` | `strftime('%Y-%m-%-d …')` – `%-d` is invalid on Windows (`ValueError: Invalid format string`), so saving the conversation fails. | Frontend writes its own conversation log (`conversation.jsonl`). | Use `%d`. |
| K09 | Low | `utils/tools.py:2608` | `pca_reducer.pkl` is dumped **before** `fit_transform`, so the saved reducer is unfitted and cannot transform new data. | Documented in the PCA output panel; reduced CSV is correct. | Dump after fitting. |
| K10 | Low | `utils/tools.py:118` | `rename_file` uses `shutil.copy2`, i.e. it copies instead of renaming. | UI labels it "Copy / rename (keeps original)". | Use `shutil.move`. |
| K11 | Low | `utils/utils.py:324-328` | `list_files_in_dir` joins the **session root** with the bare filename, dropping sub-folders, so the `*_files` lists returned by workflow tools point to non-existent paths. | Runner indexes outputs by scanning the run folder. | `os.path.join(root, file)`. |
| K12 | Medium | `utils/utils.py:476-505`, `utils/tools.py:156-164` | Missing/invalid MP key → `input()` prompt or `sys.exit(1)` inside a library call; `load_dotenv('.env')` is relative to the CWD. | Worker always injects `MP_API_KEY` from `streamlit_app/.env`, closes stdin, and converts `SystemExit` into a failed run with a friendly message. Settings has a "Test connection" button. | Raise an exception instead of exiting/prompting. |
| K13 | Low | `utils/tools.py:183` | `mpr.get_structure_by_material_id` is called after the `with MPRester(...)` block has exited (works today, but relies on the client not being closed). | none needed (if it starts failing the run fails cleanly). | Keep calls inside the context manager. |
| K14 | Low | `utils/tools.py:188` | Comment for the most stable POSCAR uses `docs[0].symmetry` instead of the symmetry of the most stable entry. | Candidate table in the UI shows the correct per-entry symmetry from MP. | Use the doc that matches `mid_0`. |
| K15 | Low | `utils/schemas.py:815-873` | `GenerateInterfaceFromPoscars.validator` does not `return self`. Works with the installed pydantic (2.13) but is deprecated behaviour. | none needed. | Add `return self`. |
| K16 | Medium | `utils/tools.py:2283-2299` | MLP calculators are created without a device argument; Orb-v3 is hard-coded to `device='cpu'`. There is no way to choose CPU/GPU. | Device selector sets `CUDA_VISIBLE_DEVICES=""` in the worker for CPU runs (affects SevenNet, CHGNet, MatterSim, Optuna/training). Orb-v3 always runs on CPU – shown in the UI. | Add a `device` parameter. |
| K17 | Low | `utils/tools.py:319` | Slurm tool metadata lists `mail_type`/`mail_user` but the function does not accept them, and the result has no `script_path` key. | UI exposes only the accepted fields; output discovered from the run folder. | Add the parameters or drop them from metadata. |
| K18 | Low | `utils/tools.py:513-517` | `customize_vasp_kpoints_with_accuracy` does not pass `custom_kppa` to the schema, so `Custom` with `custom_kppa=None` passes validation and crashes later. | UI requires `custom_kppa ≥ 1` when "Custom" is selected. | Validate `custom_kppa` when `accuracy_level == 'Custom'`. |
| K19 | Low | `utils/tools.py` (analysis tools 1593–2146) | Analysis tools write their outputs **into the input folder** and only check `os.path.exists` without using the result. | UI copies the uploaded/selected folder into the run's `files/` before analysis, so source data is never modified. | Validate the folder and write outputs to the session dir. |
| K20 | Info | `utils/tools.py:2898-2964` | `model_prediction_for_AlMgSiSc` only works for compositions present in the bundled grid (0.01 wt.% steps; exact float equality). Off-grid values raise `IndexError`. | Sliders/number inputs use 0.01 wt.% steps and round before submitting. | Snap to the nearest grid point. |
| K21 | Info | `utils/utils.py:9-245` | `visualize_structure` HTML loads 3Dmol.js from `https://3Dmol.org` at view time (needs internet). | In-app viewer loads 3Dmol from cdnjs and is shown for every structure; the Masgent HTML is still produced and downloadable. | – |
| K22 | High (AI, xAI provider) | `ai_mode/ai_backend.py:319` | Imports `pydantic_ai.providers.grok`, which does not exist in the installed pydantic-ai 2.43 (renamed `xai`, and that one needs the optional `xai-sdk`). Choosing xAI crashes Masgent's AI mode. | Frontend talks to xAI's OpenAI-compatible endpoint (`https://api.x.ai/v1`) with `OpenAIProvider`, model `grok-4-1-fast-non-reasoning`. | Use `OpenAIProvider(base_url='https://api.x.ai/v1')` or pin pydantic-ai. |
| K23 | High (Windows) | `utils/interface_maker.py:103-104, 232` | Slab/interface file names are derived with `path.split("/")[-1]`, so Windows paths with backslashes produce invalid names (`slab_001_C:\...`) and the interface builder fails with "No such file or directory". Works in the CLI only because it uses bare file names. | The frontend passes every staged input path with forward slashes (`Path.as_posix()`), which Windows accepts. | Use `Path(path).stem`. |
| K24 | High (AI, all providers) | `ai_mode/ai_backend.py:387` | `Agent(..., history_processors=[...])` is no longer accepted by the installed pydantic-ai 2.43 (`TypeError: unexpected keyword argument 'history_processors'`), so Masgent's AI mode cannot even build the agent. | Frontend passes the same 20-message window via `capabilities=[ProcessHistory(keep_recent_messages)]` (falls back to the old keyword on older pydantic-ai). | Pin `pydantic-ai<2` in `pyproject.toml`, or migrate to `ProcessHistory`. |
| K25 | High (security) | `utils/tools.py:110-111` | `rename_file` checks `str(base_dir / new_name).startswith(str(base_dir))` on an **unresolved** path, so `new_name='../x'` passes and the file is written outside the session folder (the AI agent can trigger this). `read_file` has no check at all. | The run manager rejects `name`/`new_name` that escape the session folder (`safe_join`) before any worker starts; tested in `tests/test_runner.py::test_masgent_file_tools`. | Compare `new_path.resolve()` against `base_dir.resolve()` (and do the same in `read_file`). |

## Environment issues found on this machine (not Masgent bugs)

| ID | Problem | Effect | Fix |
|---|---|---|---|
| E01 | The installed `torch 2.14.0+cpu` is a **CPU-only** build. | The RTX 5050 is not used; all ML runs on CPU. | Install the CUDA 13.0 build (see README_STREAMLIT.md → GPU). |
| E02 | torch's bundled top-level `functorch` package is **missing on disk** (listed in `torch-2.14.0.dist-info/RECORD`, files absent), so `torch.compile` fails. | Orb-v3 fails with `No module named 'functorch'`; SevenNet, CHGNet and MatterSim work. | Reinstalling torch restores it (the same command as E01). The Setup doctor detects this. |
| E03 | No POTCAR library (`PMG_VASP_PSP_DIR`) is configured. | Workflow generators write `POTCAR*.spec` placeholders (K01). | Optional: set the library in Settings → Computation. |
